                the web app accepts a component list upload, stores it in mongodb using <a href="https://nextjs.org/docs/pages/building-your-application/routing/dynamic-routes" target="_blank" className="a">dynamic routing</a>, and generates a unique qr code that the mobile app can scan.

                the mobile app scans the qr, downloads the parsed list, then runs a fast color-based segmentation to isolate the breadboard, estimate its corners, and flatten it to a top-down view. 
                
                histogram projections reveal the repeating hole grid so each cell can be mapped precisely. with that structure in place, the app overlays steps, components, and wiring onto each cell.

           <span className='text-lightBeige/95 text-lg mt-5'>chaining async operations</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>

            <span className='text-lightBeige/95 text-lg mt-5'>1 | detecting the breadboard in frame</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                the first challenge: finding a white breadboard in frame and getting a normalized top-down view.
        
                <span className="route-background text-[0.9rem]">server/app/src/AR.kt</span>

                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-kotlin'>{`// HSV thresholding to isolate white breadboard
val lowerWhite = Scalar(0.0, 0.0, 200.0)
val upperWhite = Scalar(180.0, 50.0, 255.0)
val mask = Mat()
Core.inRange(hsv, lowerWhite, upperWhite, mask)

// ... morphological cleanup, then Imgproc.findContours(mask, contours, ...)

// Largest contour is assumed to be the breadboard
val maxContour = contours.maxByOrNull { Imgproc.contourArea(it) }
`}</code>
                    </pre>
                </div>

                guideline thresholds for white objects with opencv (low saturation, high value in <a href="https://docs.opencv.org/4.x/df/d9d/tutorial_py_colorspaces.html" target="_blank" className="a">hsv</a>), then finds the biggest blob. <a href="https://docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html" target="_blank" className="a">morphological operations</a> clean up the noise before <a href="https://docs.opencv.org/4.x/d4/d73/tutorial_py_contours_begin.html" target="_blank" className="a">contour detection</a>.
            </span>
            <span className='text-lightBeige/95 text-lg'>2 | perspective transform logic</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                once the four corners are obtained, the breadboard is <span className='text-lightBeige/95 font-normal'>warped </span> into a flat rectangle. this makes grid detection consistent regardless of camera angle.

                <span className="route-background text-[0.9rem]">server/app/src/AR.kt</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-kotlin'>{`// srcMat: the 4 sorted corners, dstMat: corners of a flat rectangle
val transformMatrix = Imgproc.getPerspectiveTransform(srcMat, dstMat)

// Store inverse for mapping points back to original view
inverseTransformMatrix = Imgproc.getPerspectiveTransform(dstMat, srcMat)

Imgproc.warpPerspective(source, warped, transformMatrix, normalizedSize)
`}</code>
                    </pre>
                </div>

                <span className='text-lightBeige/95 font-normal'>problem: </span>grid points are detected in the warped rectangle, but highlights need to be drawn in the original camera frame. 
                
                our solution was using the <a href="https://docs.opencv.org/4.x/d2/de8/group__core__array.html#gad327659ac03e5fd6894b90025e6900a7" target="_blank" className="a">inverse perspective transform</a>, which maps coordinates back using <a href="https://en.wikipedia.org/wiki/Homogeneous_coordinates" target="_blank" className="a">homogeneous coordinates</a>.
            </span>

            <span className='text-lightBeige/95 text-lg'>3 | grid detection with histogram analysis</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                next, guideline finds where the holes exist on the breadboard, which are the <span className='text-lightBeige/95 font-normal'>intersection of rows and cols. </span><a href="https://homepages.inf.ed.ac.uk/rbf/HIPR2/project.htm" target="_blank" className="a">histogram projection</a> counts white pixels in each row and column, smooths the signal with <a href="https://en.wikipedia.org/wiki/Gaussian_filter" target="_blank" className="a">gaussian filtering</a>, and finds peaks (the grid lines).

                <span className="route-background text-[0.9rem]">server/app/src/AR.kt</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-kotlin'>{`// ... adaptive threshold the warped image into binary

// Count white pixels per row/column
for (y in 0 until binary.height()) {
    for (x in 0 until binary.width()) {
        if (binary.get(y, x)[0] > 0) {
            horizontalProjection[y]++
            verticalProjection[x]++
        }
    }
}

// Smooth and detect peaks (same for vertical)
val smoothedHorizontal = smoothArray(horizontalProjection)
val horizontalPeaks = detectPeaks(smoothedHorizontal, binary.height())

// ... each peak becomes a grid line (horizontalLines, verticalLines)
`}</code>
                    </pre>
                </div>
            </span>

            <span className='text-lightBeige/95 text-lg mt-5'>4 | building the intersection matrix</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                now every grid intersection is computed and stored in a 2d array. this becomes our "map" of the breadboard.

                <span className="route-background text-[0.9rem]">server/app/src/AR.kt</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-kotlin'>{`val matrix = Array(horizontalLines.size) { row ->
    Array<Point?>(verticalLines.size) { col ->
        findIntersection(horizontalLines[row], verticalLines[col])
    }
}
`}</code>
                    </pre>
                </div>

                now <span className='text-lightBeige/95 font-normal'>matrix[5][12]</span> gives us the exact pixel coordinates of row 5, column 12.
            </span>

            <span className='text-lightBeige/95 text-lg'>5 | sequential pin highlighting</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                this is where the magic happens. the app cycles through components and their pins automatically.
                
                <span className="route-background text-[0.9rem]">server/app/src/AR.kt</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-kotlin'>{`// Runs every frame, advances once per PIN_HIGHLIGHT_DELAY_MS
val now = System.currentTimeMillis()
if (now - lastUpdateTime >= PIN_HIGHLIGHT_DELAY_MS) {
    clearHighlightedPoints()
    val component = placements[currentComponentIndex]

    if (currentPinIndex < component.positions.size) {
        val (row, col) = component.positions[currentPinIndex]
        highlightGridPoint(row, col)
        // ... show "\${component.ref} - Pin N" on screen
        currentPinIndex++
    } else {
        // Move to next component
        currentComponentIndex = (currentComponentIndex + 1) % placements.size
        currentPinIndex = 0
    }

    lastUpdateTime = now
}
`}</code>
                    </pre>
                </div>

                this implements a <a href="https://en.wikipedia.org/wiki/Finite-state_machine" target="_blank" className="a">state machine</a> that walks through each component's pins. 
                
                <Image
                    src="/work/guideline/state.png"
                    alt="guideline-state"
                    width={1200}
                    height={800}
                    className="w-full h-auto object-cover rounded"
                    sizes="(max-width: 768px) 100vw, (max-width: 1280px) 100vw, 1600px"
                    quality={75}
            loading="lazy"
            decoding="async"
                />

                when it finishes one component, it moves to the next. when it finishes all components, it loops back. timing is controlled by checking <a href="https://developer.android.com/reference/java/lang/System#currentTimeMillis()" target="_blank" className="a">System.currentTimeMillis()</a> for frame-independent delays.
            </span>

            <span className='text-lightBeige/95 text-lg'>6 | mapping highlights back to camera view</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                everything is detected in the warped view, but users see the camera feed. so each highlight point must be transformed back using the inverse matrix.

                <span className="route-background text-[0.9rem]">server/app/src/AR.kt</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-kotlin'>{`highlightedPoints.forEach { (row, col) ->
    matrix[row][col]?.let {
        // Map from warped to original view
        val originalPoint = mapPointFromWarpedToOriginal(it)

        Imgproc.circle(rgba, originalPoint, 8, CYAN, -1)
        Imgproc.putText(rgba, "($row,$col)", originalPoint, FONT, 0.5, WHITE, 1)
    }
}
`}</code>
                    </pre>
                </div>

                the result: bright dots with coordinates that follow the breadboard as you move it around.
