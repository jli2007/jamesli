            <span id="redis" className='text-lightBeige/95 text-lg'>redis</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                i used redis as a <span className='text-lightBeige/95 font-normal'>low-latency cache and session store</span> to avoid repeated database calls and to keep auth stateless.

                user data is cached in redis hashes with a short ttl, while auth sessions are stored as token → user mappings.

                <span className="route-background text-[0.9rem]">server/lib/redis/caching.ts</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-ts'>{`await redis.hset(\`userdata:\${user.id}\`, {
    username: user.username,
    currency: user.currency,
    inventory_plants: JSON.stringify(user.inventory_plants),
    inventory_animals: JSON.stringify(user.inventory_animals),
    location: JSON.stringify(user.location),
});
await redis.expire(\`userdata:\${user.id}\`, 60 * 5); // 5 min cache
`}</code>
                    </pre>
                </div>

                this allows the backend to <span className='text-lightBeige/95 font-normal'>serve frequent reads from memory</span> instead of postgres, reducing latency and load.

                sessions are stored separately using expiring keys, so logging out is as simple as deleting a redis entry.
            </span>


            <span className='text-lightBeige/95 text-xl'>rabbitmq</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                i used rabbit as the <span className='text-lightBeige/95 font-normal'>event backbone</span> for the backend. instead of performing database writes directly in the main request lifecycle, events are published to queues and processed asynchronously by subscribers. 
                
                this makes gameplay responsive and allows heavy background tasks to be offloaded without slowing the app down.

                <span className="route-background text-[0.9rem]">server/lib/rabbitmq/rabbitmq.ts</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-ts'>{`// publish game event to queue
await channel.assertQueue("game_events", { durable: true });
channel.sendToQueue("game_events", Buffer.from(JSON.stringify({
    sessionToken,
    eventType: "level_up",
    data: { newLevel: 5 }
})), { persistent: true });
`}</code>
                    </pre>
                </div>

                events cover <span className='text-lightBeige/95 font-normal'>gameplay actions, collection updates, social interactions, location tracking, chat messages, and analytics</span>. 
                subscribers consume the queues, validate sessions using <a href="#redis" className="a">redis</a>, and then update postgres or perform other side effects.

                <span className="route-background text-[0.9rem]">server/lib/rabbitmq/subscribers.ts</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-ts'>{`channel.consume("game_events", async (msg) => {
    if (!msg) return;
    const { sessionToken, eventType, data } = JSON.parse(msg.content.toString());
    
    // fetch userId from redis session
    const payload = await redis.get(\`session:\${sessionToken}\`);
    if (!payload) {
        console.error("No session found for token", sessionToken);
        return channel.ack(msg);
    }

    const { userId } = JSON.parse(payload);

    // call the appropriate handler
    const handler = gameEventHandlers[eventType];
    if (handler) await handler(userId, eventType, data);

    channel.ack(msg);
});`}</code>
                    </pre>
                </div>

                this setup is scalable, as events are handled in parallel and logic layers are separated to reduce coupling.

                exchanges are also used to <span className='text-lightBeige/95 font-normal'>route events to multiple queues</span>. for example, a collection event can be sent to both the game logic queue and an analytics queue simultaneously:

                <span className="route-background text-[0.9rem]">server/lib/rabbitmq/rabbitmq.ts</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-ts'>{`channel.publish("game_exchange", "collection_events", Buffer.from(JSON.stringify({
    sessionToken,
    column: "inventory_animals",
    body: { new: "lion" }
})), { persistent: true });
`}</code>
                    </pre>
                </div>

                this architecture ensures that <span className='text-lightBeige/95 font-normal'>gameplay events, analytics, and background jobs</span> can scale independently: makes the whole backend easier to navigate and debug.
            </span>

            <span className='text-lightBeige/95 text-xl'>security scripts</span>
            <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                i used bash scripts to set up secure configurations for redis, rabbitmq, and the application environment. one of the main uses cases was <span className='text-lightBeige/95 font-normal'>setting strong secret variables</span>.

                <span className="route-background text-[0.9rem]">/setup-security.sh</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-bash'>{`#!/bin/bash
# generate secure passwords
REDIS_PASSWORD=$(openssl rand -base64 32)
RABBITMQ_PASS=$(openssl rand -base64 24)
SESSION_SECRET=$(openssl rand -base64 64)

# create .env with strong secrets
cat > .env << EOF
REDIS_PASSWORD=\${REDIS_PASSWORD}
RABBITMQ_PASS=\${RABBITMQ_PASS}
SESSION_SECRET=\${SESSION_SECRET}
EOF

# secure Redis and RabbitMQ configs
chmod 600 .env
`}</code>
                    </pre>
                </div>

                the whole script automatically generates environment secrets, sets restrictive permissions, and creates monitoring tables for logging security events in supabase.

            <span className='text-lightBeige/95 text-xl'>docker + kubernetes architecture</span>
                <span className='text-lighterBeige font-inter font-extralight text-[1rem]'>
                    our backend uses <span className='text-lightBeige/95 font-normal'>docker for containerization</span>  and <span className='text-lightBeige/95 font-normal'>kubernetes for orchestration</span>. each service, the server, redis, and rabbitmq, runs isolated in its own container.

                    <span className="route-background text-[0.9rem]">dockerfile</span>
                    <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                        <pre className='line-numbers'>
                            <code className='language-bash'>{`FROM node:22.14.0-alpine AS prod
ENV NODE_ENV=production
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY --from=builder /app/dist ./dist
USER nodejs
EXPOSE 4000
CMD ["node", "dist/index.js"]`}</code>
                    </pre>
                </div>

                i used <span className='text-lightBeige/95 font-normal'>multi-stage builds</span>: a base stage for setup and permissions, a builder stage to install dependencies and build, and dev/prod stages to optimize image size and security.

                <span className="route-background text-[0.9rem]">docker-compose.yaml</span>
                <div className='text-[0.65rem] md:text-[0.75rem] lg:text-xs'>
                    <pre className='line-numbers'>
                        <code className='language-yaml'>{`server:
  build:
    context: .
    target: dev
  environment:
    NODE_ENV: development
    REDIS_URL: redis://default:\${REDIS_PASSWORD}@redis:6379
    RABBITMQ_URL: amqp://\${RABBITMQ_USER}:\${RABBITMQ_PASS}@rabbitmq:5672
  ports:
    - "127.0.0.1:8080:4000"
  user: "1000:1000"
  networks:
    - game_network
redis:
  image: redis:7-alpine
  volumes:
    - ./redis/redis.conf:/usr/local/etc/redis/redis.conf
  ports:
    - "127.0.0.1:6379:6379"`}</code>
                    </pre>
                </div>

                each service communicates over <span className='text-lightBeige/95 font-normal'>an isolated bridge network</span>. redis and rabbitmq have healthchecks and resource limits to prevent overuse. ports are bound to localhost during development, and volumes persist data and configs.

                i followed a <span className='text-lightBeige/95 font-normal'>microservice design</span> for the server, it doesn't embed services. rather, it connects to them over the network. this allows the server to scale independently!

                        <code className='language-yaml'>{`apiVersion: apps/v1

  name: phuture-backend

                    </pre>

                kubernetes enforces <span className='text-lightBeige/95 font-normal'>self-healing</span>, so when pods crash, they are automatically recreated. the service exposes the backend via nodeports, supporting horizontal scaling and integration with <a href="https://kubernetes.io/docs/concepts/services-networking/ingress/" target="_blank" className="a">ingress</a>.

                the overall design separates concerns:

                server handles api requests and cron jobs, 

                redis handles caching and sessions, 

                and rabbitmq handles async events, 

                more on kubernetes networking and scaling can be found <a href="https://kubernetes.io/docs/concepts/overview/what-is-kubernetes/" target="_blank" className="a">here</a>.
